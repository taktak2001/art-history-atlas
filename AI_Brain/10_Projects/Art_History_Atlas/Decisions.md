# Decisions (ADR)

重要な設計判断を Architecture Decision Record 形式で記録する。各項目: 文脈 / 決定 / 根拠 / 代替案 / 状態。

## ADR-001: ホスティングに GitHub Pages を採用

- **文脈**: 閲覧専用の静的サイト。当初 Phase 1 は Vercel 想定だったが、ユーザー要望で GitHub Pages へ移行。
- **決定**: GitHub Pages（Actions デプロイ）で公開。プロジェクトサイト（サブパス `/art-history-atlas/`）。
- **根拠**: 無料・GitHub と一体・サーバー不要。静的エクスポートと相性良好。
- **代替案**: Vercel（要トークン、今回未使用）、Netlify。`basePath` を外せば移行可能。
- **状態**: 採用・本番稼働。

## ADR-002: 静的生成（`output: 'export'`）

- **文脈**: 認証もサーバーロジックも不要な閲覧アプリ。
- **決定**: Next.js の静的エクスポートで完全静的化。動的ルートは `generateStaticParams`。
- **根拠**: 高速な初期表示、ゼロ運用費、任意 CDN 配信、SEO 良好。
- **代替案**: SSR/ISR（不要な複雑性）、SPA（SEO/初期表示で不利）。
- **状態**: 採用。

## ADR-003: CMS を導入しない

- **文脈**: データは構造化（関係エッジ・比較・検索）され、整合性検証が重要。編集者は限定的。
- **決定**: 静的 TypeScript モジュール + Zod 検証で管理。CMS なし。
- **根拠**: 型安全・参照整合性を CI で担保・ビルド単純・実行時依存ゼロ。100件超まで拡張可能。
- **代替案**: Markdown/MDX（構造化データの整合性に不利）、Headless CMS（運用/費用増）。
- **状態**: 採用。

## ADR-004: Supabase / バックエンドを使わない

- **文脈**: MVP は閲覧中心。ユーザーアカウント・保存機能は非対象。
- **決定**: 常時稼働バックエンドを持たない。
- **根拠**: 要件で不要。費用・複雑性・攻撃面を回避。将来編集ワークフローが必要なら再検討。
- **代替案**: Supabase（将来の選択肢として保留）。
- **状態**: 採用。

## ADR-005: PWA にする（手書き Service Worker）

- **文脈**: モバイル鑑賞・オフライン閲覧・ホーム画面追加の要件。
- **決定**: manifest + 手書き SW。`next-pwa` 等に依存しない。
- **根拠**: バージョン付きキャッシュを完全制御（更新時に旧キャッシュ削除）。サブパス配信に自作で対応。画像キャッシュを件数上限で制御。
- **代替案**: `next-pwa`（設定がブラックボックス化、サブパス制御が面倒）。
- **状態**: 採用。SW VERSION=`v2`。

## ADR-006: 図（タイムライン/ネットワーク）を自作 SVG/DOM で実装

- **決定**: d3-force / vis-network / react-flow 等を使わず、決定的レイアウト + SVGベジェ/DOM で自作。
- **根拠**: バンドル削減、静的化との相性、「時代の流れ」を決定的配置で読みやすく、アクセシビリティ（フォーカス/テキスト代替）を制御しやすい。
- **代替案**: D3/visx 等（高機能だが過剰・重い）。
- **状態**: 採用。両図にテキスト代替を併設。

## ADR-007: 作品画像を慎重に扱う（PD のみ・hotlink・onError フォールバック）

- **文脈**: 著作権・ライセンス順守が最優先。かつ本環境は画像ホストへ egress 不可。
- **決定**: Wikimedia Commons の PD 2次元作品のみを、公式 `Special:FilePath` で hotlink。ファイル名は WebSearch で確認（推測しない）。読み込み失敗は `onError` でプレースホルダー。20世紀著作権作品はプレースホルダー。
- **根拠**: 「架空/推測 URL 禁止」「出典不明画像禁止」を満たしつつ、egress 制約下で実画像を提示。壊れ画像を本番に出さない。
- **代替案**: ローカル保存 + WebP 最適化（egress 許可環境で将来実施。ADR-008）。CC-BY の3D/建築（帰属確定が必要、今回見送り）。
- **状態**: 採用（41点）。license-confirmed / byte-verified は未達（`Image_Policy.md`）。

## ADR-008: 画像はローカル最適化を将来行う（現状は hotlink）

- **決定**: egress が使える環境で、各 PD 画像を取得し WebP/AVIF 化してリポジトリに保存、`fileUrl` をローカルパスへ。`provider`/`sourceUrl`/`license` は保持。
- **根拠**: 配信安定性・パフォーマンス・Commons 依存の低減。
- **状態**: 保留（TODO）。現状は hotlink + SW 画像キャッシュ上限で運用。

## ADR-009: AI チャット / クイズ / アカウント等を入れない（MVP 非対象）

- **決定**: ログイン・アカウント・お気に入り・学習済み管理・クイズ・個人ノート・コメント・SNS・課金・管理画面・AIチャット・実行時スクレイピングを実装しない。
- **根拠**: MVP の複雑性を上げない。要件で非対象。将来追加しやすい構造は保つ。
- **状態**: 採用（Phase 2 も維持）。将来案は `TODO.md` 長期。

## ADR-010: `worksOf`/`artistsOf` を movementId から導出

- **決定**: movement 側の `workIds/artistIds` 手動配列に依存せず、作品・作家側の `movementIds` から導出。
- **根拠**: 作品追加時に movement を編集不要（整合性崩れを防ぐ）。画像付きを先頭化して代表作を見せやすい。
- **状態**: 採用（Phase 2）。

## 決定：画像を利用根拠（usageBasis）で区別する（2026-08）

- **決定**: 権利未確認画像を一律掲載せず、`public-domain / licensed / quotation / unavailable` を `ImageMeta.usageBasis` として区別。`quotation` は分析本文と一体の限定サーフェスで、`editorial-approved` かつ `isPublished` のときだけ表示。
- **なぜ**: 「引用」を装飾・代表作品展示に流用すると本文が従・画像が主になり、引用要件（主従関係・明確な区別・目的上の正当な範囲）を満たさないため。
- **無移行の導出**: 既存の約 N 件の確認済み画像に `usageBasis` を一括付与せず、`resolveUsageBasis()` で導出する（並行編集下での差分・衝突を抑えるため）。必要なら後日、明示バックフィルを follow-up にできる。
- **image:null の一括変換をしない**: 権利未確認作品を自動で `quotation` にしない。個別監査で条件を満たすものだけ候補化する。
- **限界**: 仕組みは適法性を保証しない。重要作品の本番掲載前は IP 専門家レビューを推奨。

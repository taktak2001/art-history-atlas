# アーキテクチャと技術選定

本ドキュメントは、美術史アトラスの技術構成の判断と代替案を記録する。

## 要件の要点

- Vercel への容易なデプロイ、TypeScript の型安全、静的生成／高速初期表示、PWA 対応、検索性能、大量の時系列データへの拡張性、図（タイムライン・ネットワーク）の描画性能、アクセシビリティ、保守性、テスト容易性、**不要なバックエンドを持たない**こと。
- 閲覧中心の MVP。ユーザー認証・CMS・常時稼働バックエンドは不要なら導入しない。

## 採用構成と理由

### フレームワーク：Next.js 15（App Router / `output: 'export'`）

- **理由**：Vercel との親和性が最も高い。App Router により静的生成（SSG）と `generateStaticParams` で全詳細ページを事前生成でき、初期表示が速い。ルーティング・メタデータ・画像・コード分割が標準で揃う。
- **静的エクスポート**を選択：閲覧専用でサーバーロジックが不要なため、完全な静的サイト（`out/`）として任意の CDN に載る。ランタイムのサーバー費用・複雑性がゼロになる。
- **代替案**：
  - *Astro* — コンテンツ中心には好適だが、比較・ネットワーク等のインタラクティブ UI で React 島を多用するなら Next の一貫性が勝る。
  - *Vite + React SPA* — 静的生成・メタデータ・ルーティングを自前で組む必要があり、SEO/初期表示で不利。
  - *SvelteKit* — 有力だが、エコシステムとチームの習熟、Vercel の一級サポートで Next を優先。

### 言語：TypeScript（strict）＋ Zod

- データスキーマを Zod で единый（単一ソース）に定義し、そこから型を生成（`z.infer`）。ビルド前の検証スクリプトと実行時の一貫性を両立。

### データ保存：静的 TypeScript モジュール

- **理由**：MVP は 30 件、将来 100 件超でも、静的 JSON 相当のデータを **型付き TS モジュール**で持つのが最も単純かつ堅牢。ビルド時にツリーシェイクされ、実行時に外部 API へ依存しない（要件の「実行時の無制御な依存を避ける」に合致）。参照整合性を TS＋Zod で保証できる。
- **代替案**：
  - *Markdown/MDX* — 長文記事には好適だが、関係エッジ・比較・検索など**構造化データ**の整合性検証には TS+Zod が優れる。
  - *SQLite（sql.js / better-sqlite3）* — クエリは強力だが、静的サイトでの配信・型連携・ビルドの単純さで TS モジュールに劣る。100 件規模では不要。
  - *Supabase 等の BaaS* — 常時稼働バックエンドは要件で不要とされ、費用・複雑性が増すため不採用。将来的に編集ワークフローが必要になった場合の選択肢。

### 図の描画：自作 SVG / DOM

- **タイムライン**：DOM の絶対配置＋横スクロール、ポインタでドラッグ、Ctrl+ホイールでズーム。重いチャートライブラリを避け、バンドルを小さく保つ。
- **ネットワーク**：時代順のカラムに決定的レイアウトでノードを配置し、エッジは SVG のベジェで描画。力学シミュレーション（d3-force 等）は不要で、決定的配置の方が「時代の流れ」を読み取りやすい。ノードは DOM ボタンにしてアクセシビリティ（フォーカス・キーボード）を確保。
- **ネットワークの描画レイヤー**：通常時は `base edges → nodes → labels`。ノードまたは関係選択時は `dimmed nodes → highlighted edges → selected/related nodes → labels` の順に、別SVGとDOMレイヤーで描画する。強調線は無関係ノードの上を通せるが、選択・関連ノードの背後に留める。
- **ネットワーク操作**：データ量に応じた横長キャンバスを横スクロール領域に置き、マウスドラッグ、トラックパッド横スクロール、Shift＋ホイール、左右キー、時代ジャンプ、選択対象の中央寄せを同じ `scrollLeft` 制御へ集約する。`prefers-reduced-motion` 時は中央寄せを即時移動にする。
- **関係表示密度**：`important` は継承・反発・収録済みの主要な影響、`all` は有効な関係タイプ全件。切替と件数はPC・スマートフォン共通のstickyコントロールに置く。モバイルの `important` は最大18関係・24ノードに制限する。
- **線の操作と代替**：有向線は矢印、種類は `stroke-dasharray`、選択可能領域は透明な太いSVGパスで確保する。図と同じ絞り込み結果をボタン形式のテキスト関係一覧にも出し、線を直接操作できない利用者にも同じ選択パネルを提供する。
- **テキスト代替**：両図に同じ情報へアクセスできる表／リストを併設（アクセシビリティ要件）。
- **代替案**：*D3 / visx / react-flow / vis-network* — 高機能だがバンドル増・学習コスト・SSR/静的化の相性で、要件規模には過剰と判断。

### 検索：クライアント側の軽量インデックス

- 全エンティティから `haystack` 文字列を生成し、AND 部分一致で絞り込む（`src/lib/dataset.ts`）。30〜100 件規模では十分高速で、追加依存が不要。将来的に件数が増えれば FlexSearch/MiniSearch 等の事前生成インデックスへ移行可能。

### 表示する範囲（LOD）とムーブメント階層

- `src/lib/movement-hierarchy.ts` を、LODフィルタ・親子ツリー・非因果グループ・ネットワーク縮約の単一窓口とする。
- LODは `core`（基本）→ `standard`（充実）→ `detailed`（すべて）の累積表示。現在の30件は基本24件、充実30件、すべて30件。
- 初期値は学習目的に合わせる。横型タイムラインは通史を `core`、時代別を `standard` とし、縦型年表・マトリクス・ネットワーク・一覧は `core` から開始する。
- 選択値は `?lod=` に保存する。URLを共有・再読込しても状態が再現され、既存の比較用URLとは独立する。
- `parentMovementId` は「主要ムーブメント→サブムーブメント」という分類上の包含だけを表す。影響・継承・反発は引き続き `Relationship` の独立エッジとして扱い、親子関係から推測しない。
- `groupId` は検索と縮約表示のための非因果的なまとまり。代表項目は `MOVEMENT_GROUPS` で明示し、グループ自体を歴史的因果として表示しない。
- ネットワークでは非表示ノードをDOMへ描画せず、エッジ端点だけを表示中の祖先またはグループ代表へ集約する。元エッジIDと集約件数は保持する。
- マトリクスはセル内件数をLOD別に制限し、`+N` でそのセルだけを展開する。一覧の検索は全件を索引し、LOD外の一致には表示レベルを上げる導線を出す。
- 現在は150件規模まで、メモ化したクライアントフィルタと表示対象だけのDOM生成で対応する。さらに増える場合は一覧の仮想化と検索インデックス導入を再評価する。

### スタイル：Tailwind CSS v3＋CSS 変数

- デザインシステム（紙・墨・石の無彩色ベース、彩色は識別に限定）を CSS 変数で定義し、ライト/ダークを `data-theme` と `prefers-color-scheme` の双方で制御。フォントはシステムフォントスタックで日本語可読性と軽量性・ビルド時ネットワーク非依存を両立。

### PWA：手書き Service Worker

- **理由**：`next-pwa` 等に依存せず、バージョン付きキャッシュ（`aha-*-v1`）を自前で制御。`activate` で旧キャッシュを削除し「更新時に古いキャッシュが残らない」を保証。ナビゲーションは network-first→キャッシュ→`offline.html`、静的資産は stale-while-revalidate、閲覧ページは上限件数付きキャッシュで端末容量を圧迫しない。

## パフォーマンス方針

- 静的生成＋コード分割で初期 JS を小さく（共有 First Load JS 約 105kB）。
- 重い図（タイムライン・ネットワーク）は各ルートに閉じたクライアントコンポーネントとして分離。
- LOD外のタイムライン項目・マトリクス項目・ネットワークノードは原則としてDOMへ生成しない。
- 画像は権利確認済みのみ・明示サイズ・`loading="lazy"`。静的エクスポートのため `next/image` の最適化は無効化し、レスポンシブは CSS で対応。
- Core Web Vitals を意識（Lighthouse: Performance 81 / A11y 100 / BP 100 / SEO 100）。

## リポジトリ配置

既存リポジトリ `taktak2001/taktak` には別アプリが存在するため、本アプリは競合を避けて **`art-history-atlas/` サブディレクトリ**に独立プロジェクトとして構築した。Vercel では Root Directory を当該サブディレクトリに設定する。
